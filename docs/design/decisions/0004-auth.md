# ADR 0004: Authentication and Authorization

**Date:** 2026-10-09
**Status:** Accepted

## Context
LaPrizza requires user and role management to protect operations and identify authorized users. Customer data is personal and must be handled securely under GDPR. Several domain rules lacked explicit client clarification, requiring the team to make and document technical assumptions.

## Decision
We adopt the following mechanisms:
- **Passwords:** Hashed using Argon2 before storage. Must follow strict NIST guidelines (8-64 characters, at least one uppercase, one special character).
- **Tokens:** JSON Web Tokens (JWT) with a 1-hour expiration. This aligns with industry standards for session length. The token payload embeds the `userId` and the `Role` enum, preventing extra database lookups during authorization.
- **Roles:** Defined in the code as an enum (`MANAGER`, `EMPLOYEE`, `CUSTOMER`).
- **Endpoints:**
    - **Public route:** `/api/v1/auth/login`
    - **Protected routes:** e.g., `/api/v1/users` (middleware enforces RBAC by reading the JWT payload).
- **Data Model Relationships:** The `User` entity contains an optional `customerId`. This cleanly separates the credential record from the business profile.
- **Initialization:** A seed script injects the first `MANAGER` account upon application startup.

## Unresolved Client Questions & Assumptions
The following questions were posed to the Product Owner but remained unanswered. We established these rules to unblock development:
* **Customer Registration (User vs. Customer):** When end-customers register (creating a `User` with the `CUSTOMER` role), should we immediately require mandatory fields and generate the associated `Customer` entity? 
  * *Assumption applied:* Only `CUSTOMER` roles can possess a `customerId`. If a role changes, the `customerId` is nullified to prevent inconsistencies.
* **Registration Endpoints:** Should `MANAGER` and `EMPLOYEE` creation be strictly protected, while `CUSTOMER` creation is public?
  * *Assumption applied:* All user creation currently requires a `MANAGER` token for strict control during Sprint 1.

## Consequences
* **Positive:** Argon2 provides modern resistance against GPU attacks.
* **Positive:** Embedding roles in the JWT keeps the API stateless and performant.
* **Positive:** The 1-hour token expiration balances security with standard user experience.
* **Negative:** If token revocation becomes necessary before the 1-hour expiration, a token blacklist or refresh token rotation strategy must be implemented.
