## Description

The user opens a URL of the application, for example `/products`, from a bookmark, a link or the ☰ menu.

1. The static file server returns `index.html` for every path of the SPA (nginx `try_files … /index.html` in staging and production, the Vite server in development), and then the hashed JavaScript and CSS files.
2. `main.jsx` applies the saved theme, initializes i18next with the saved language (or the language of the browser), connects the session sync between tabs (AA04), and starts the session restore and the load of the Guest permissions ([WEB03 UC1](../role-based-navigation/navigate-with-permitted-menu.md)).
3. `app.jsx` has one route per entry of the feature registry, all inside the **Layout**. The layout is shown at once: header with the logo, the ☰ menu (filtered by the permissions), the language, the theme and the account; the breadcrumbs; the main region; the footer, which asks the back end for its health.
4. When the page needs a session or a permission, the route guard waits for the session and decides `login`, `denied` or `allow` ([WEB03 UC2](../role-based-navigation/open-page-by-url.md)). Only on `allow`, or on a public page, the code of the page is loaded (`React.lazy` of the registry loader), so a refused page never downloads its code nor requests its data.
5. The page asks for its data through the API client, directly (`api.get`) or through the hooks generated by Orval, which use the same client. The client builds the URL from `VITE_API_BASE_URL`, adds the access token kept in memory, applies the timeout and turns any failure into an `ApiError`. On `401` with a token it refreshes the session once (refresh cookie) and repeats the request.
6. The page renders the data with the identifiers returned by the back end. Every later action of the page uses the same client and the same identifiers.

The 3D viewer and the AI pages follow the same path: they are registry entries, so they are rendered inside the same layout, protected by the same guard and call the back end through the same client ([WEB06](../kitchen-configuration/README.md), [WEB07](../ai-planning/README.md)).

```mermaid
    end
    participant be as Back-end API<br/>[Container: Node.js, Express]

    activate user
    user->>files: GET /products (bookmark, link or typed URL)
    activate files
    files-->>user: index.html, then the JavaScript and CSS files
    deactivate files

    user->>boot: Load the application
    activate boot
    boot->>boot: Theme, i18next (saved or browser language), session sync between tabs
    boot->>be: POST /auth/refresh (cookie) and GET /auth/guest-permissions
    Note over boot,be: Session restore and Guest permissions, see WEB03 UC1
    be-->>boot: Session user with permissions, or 401 (Guest); Guest permissions
    boot->>routes: Render the router
    deactivate boot
    activate routes
    routes-->>user: Layout: logo, ☰ menu (permitted sections), language, theme, account, breadcrumbs, footer
    routes->>be: GET /health (back-end status in the footer)

    alt Path not in the registry
      routes-->>user: "Page not found" with a link to Home
    else Page with an access rule
      routes->>guard: resolveGuard(session status, access rule)
      activate guard
      alt Session still unknown
        guard-->>user: Loading
      else Guest without access, or session without the permission
        guard-->>user: Login (then back to this page) or "Access denied", see WEB03 UC2
      else Allowed
        guard->>page: Load the code of the page (React.lazy) and render it
      end
      deactivate guard
    else Public page
      routes->>page: Load the code of the page (React.lazy) and render it
    end
    deactivate routes

    opt Page rendered
      activate page
      page->>client: api.get('/products') or a generated Orval hook
      activate client
      client->>be: GET {VITE_API_BASE_URL}/products, Authorization: Bearer (in memory), timeout
      activate be
      be-->>client: 200 OK (JSON with the back-end ids) or error
      deactivate be
      alt 401 with an access token
        client->>be: POST /auth/refresh, then the same request once more
        be-->>client: Answer of the retry
      end
      client-->>page: Data, or ApiError { status, code }
      deactivate client
      page-->>user: Page with the data, or translated error with "Retry" (WEB04)
      deactivate page
    end
    deactivate user
```
