# ADR 0004: Authentication and Authorization

**Date:** 2026-10-09
**Status:** Accepted

## Context

LaPrizza requires user and role management to protect operations and identify authorized users (BCK01). Customer data is personal and must be handled securely, respecting data protection rules (GDPR).

## Decision

We adopt the following mechanisms for authentication and authorization:

- **Passwords:** Hashed using Argon2 before being stored in the database. Minimum length must be 8 characters and maximum length must be 64 characters. They must include special characters and, at least, one uppercase (according to)

- **Tokens:** JSON Web Tokens (JWT) with a strict 35-minute expiration. The token payload embeds the `userId` and the `Role` **enum**, preventing extra database lookups during authorization checks.

- **Roles:** Defined in the code as an enum with the values `MANAGER`, `EMPLOYEE`, and `CUSTOMER`.

- **Endpoints:**
    - **Public route:** `/api/v1/auth/login`
    - **Protected route:** `/api/v1/users` (middleware enforces the `MANAGER` role by reading the JWT payload).

- **Data Model Relationships:** The `User` entity contains an optional `customerId`. This cleanly separates the credential record from the business profile. 

- **Initialization:** A seed script injects the first `MANAGER` account upon application startup.

## Consequences

### Positive

- ´argon2` provides state-of-the-art security and modern resistance against brute-force GPU attacks;
- Embedding roles in the JWT keeps the API stateless and highly performant;
- The optional ´customerId´ avoids bidirectional coupling and strictly respects the rule that a user and a customer are distinct concepts.

### Negative

- The 35-minute strict expiration means users will be logged out frequently. If this impacts usability, a refresh token strategy will be required in the future.
