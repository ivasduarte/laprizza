# Frontend

Single-Page Application (SPA) of the LaPrizza information system (WEB01).
Technology and structure are justified in [ADR-0007](../docs/adr/0007-web-application-%28spa%29-technology-and-structure.md); the structure, the configuration of each environment and the common layout are documented in [Web Application (WEB01, WEB02)](../docs/flows/web-application/README.md).

## Requirements

- **Node.js:** `v22.x` (LTS)
- **Package Manager:** `npm` `v10.x` (bundled with Node.js 22)

## Installation

From the repository root, navigate to the `frontend` directory and install the dependencies:

```bash
cd frontend
npm ci
```

## Configuration

Copy `.env.example` to `.env` (never committed) and adjust it for your environment.

| Variable            | Purpose                                                         | Example                        |
| ------------------- | --------------------------------------------------------------- | ------------------------------ |
| `VITE_PORT`         | Dev server port                                                 | `4200`                         |
| `VITE_ORIGIN`       | Dev server origin (must match the back-end CORS allowed origin) | `http://localhost:4200`        |
| `VITE_API_BASE_URL` | Base URL of the back-end REST API, including the version prefix | `http://localhost:3000/api/v2` |
| `VITE_HTTP_TIMEOUT_MS`, `VITE_HTTP_MUTATION_TIMEOUT_MS` | Timeouts (ms) of reads and writes; defaults 15000 and 30000 | `16000`, `35000` |

> **Important:** every `VITE_*` variable is embedded in the public bundle. Never put passwords, tokens or any other secret in them. Credentials and tokens must never be stored in the application files.

For staging and production the build is made by the deployment pipeline (`deploy/laprizza-deploy-web.sh`) with `VITE_API_BASE_URL=/api/v2`: nginx serves the SPA and forwards `/api/` to the back end on the same origin.

## Scripts

| Command           | Description                           |
| ----------------- | ------------------------------------- |
| `npm run dev`     | Start the dev server                  |
| `npm run build`   | Production build into `dist/`         |
| `npm run preview` | Serve the production build locally    |
| `npm test`        | Run the unit tests (Node test runner) |
| `npm run lint`    | Run ESLint                            |
| `npm run format`  | Format with Prettier                  |
| `npm run test:e2e` | Run the end-to-end tests (Playwright) |
| `npm run generate:api` | Regenerate the API client from `backend/src/api/openapi.v2.json` (Orval) |

## Structure

```
src/
  main.jsx                entry point: theme, i18n, session restore, router
  app.jsx                 routes generated from the feature registry, inside the layout
  features/
    registry.js           list of pages: id, path, label, access rule, menu section, lazy loader
    navigation.js         menu sections and breadcrumbs
    <feature>/            one folder per page (catalogue, stock, kitchen-configuration, visualization3d, ai, users, ...)
  api/
    generated/, model/    client generated by Orval from the OpenAPI document
    orval-mutator.js      sends the generated calls through shared/api
  shared/
    api/                  HTTP client (single access point to the REST API)
    auth/                 session, Guest permissions, route guard, useCan
    ui/                   layout, logo, language switcher, theme, breadcrumbs, feedback
    i18n/                 English and Portuguese texts
    forms/, feedback/     validation, submit guard, toasts, confirmation dialogs
```

### Adding a feature

1. Create `src/features/<name>/<name>-page.jsx` with a default-exported component.
2. Add an entry to `src/features/registry.js` (access rule `requiresAuth` / `permission`, menu section `navGroup`) and its menu text in both languages.
3. Call the back end only through `src/shared/api` (`import { api } from '../../shared/api/index.js'`).

The 3D viewer (`visualization3d`, `kitchen-configuration`) and the AI pages (`ai`) are registered like any other feature, so they are rendered inside the common layout and use the same API client.
